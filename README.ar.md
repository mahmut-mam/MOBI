# موبي ستور — نسخة التطوير 0.2

برنامج ويندوز عربي لمحل إكسسوارات الموبايل، مع خادم محلي وقاعدة SQL Server Express مستقلة. اسم «موبي ستور» مؤقت وقابل للتغيير.

الواجهة المحدثة تستخدم هوية كحلية وزمردية، ومدير قواعد ببطاقات، وشاشة دخول بشعار هاتف بحرف M. تعتمد الرئيسية قوائم علوية وشريط اختصارات حسب الصلاحيات ولوحة جانبية للتاريخ، مع تنسيق موحد لحقول البطاقات والفواتير والجداول. أصول الشعار بصيغ SVG وPNG وICO في `src/MobiStore.Desktop/Assets`.

## التشغيل على هذا الجهاز

1. افتح `Start-MobiStore.cmd`، أو نفّذ `scripts/start.ps1` من PowerShell.
2. يشغّل المشغل الخادم المحلي على `http://127.0.0.1:5188` ثم برنامج ويندوز.
3. اختر قاعدة من نافذة إدارة القواعد واضغط «فتح القاعدة»، أو «إنشاء جديد» لإنشاء قاعدة مستقلة على نفس SQL Server. يمكن تسجيل قاعدة موبي ستور موجودة عبر «إضافة موجودة». عند فتح قاعدة جديدة أدخل اسم المحل والعملة الأساسية وحساب المدير وكلمة مرور من 12 حرفًا على الأقل. لا توجد كلمة مرور جاهزة.
4. أنشئ المواد والعملاء والموظفين. افتح وردية، وأدخل مشتريات لتوفير رصيد، ثم جرّب البيع والتحصيل والإغلاق ببيانات تجريبية.

قاعدة التطوير الافتراضية: `MobiStore_Development` على `.\SQLEXPRESS`، باستخدام حساب Windows. لا يقرأ المشروع أي بيانات من برنامج المحاسبة الذهبية ولا يعدّل ملفاته أو قواعده.

حزمة .NET SDK محلية في المجلد المجاور `../.tools/dotnet`. المشغل يستعملها إن كانت موجودة. نقل المشروع لجهاز آخر يحتاج .NET 10 Desktop Runtime وASP.NET Core Runtime، أو حزمة نشر ذاتية الاحتواء لم تُنتج بعد.

تفاصيل تحديث 0.2 وطريقة اختيار مسار النسخ اليدوي في [دليل التحديث](docs/RELEASE-0.2.ar.md).

## المنفذ فعليًا

- إدارة قواعد متعددة: اختيار وإنشاء وتسجيل قاعدة، وخيار فتح الأخيرة، وعزل جلسات الدخول والعملة والبيانات بين القواعد. التفاصيل والمتبقي في `docs/DATABASE-MANAGER.ar.md`.
- إعداد المنشأة واختيار USD أو SYP، وإنشاء المدير وتسجيل الدخول والخروج وجلسات انتهاء صلاحيتها بعد 8 ساعات.
- مستخدمون مستقلون وصلاحيات خدمة، وحجب التكلفة والأرصدة عن غير المخوّلين.
- مواد وباركودات ووحدات متعددة وماركات وتوافق وألوان وصور من الجهاز، وأسعار جملة ومفرق وخاصة بالعميل، ونشر اختياري للكتالوج.
- مسح باركود وتعليق واسترجاع الفواتير واختصارات البيع F2/F8/F9.
- تحويل مستودعات وجرد يتحقق من الرصيد المتوقع وقيد عجز/فائض، ومرتجعات شراء وحساب مورد ودفعات من صندوق المدير.
- تعديل صلاحيات المستخدم وإيقاف الموظف مع إنهاء الجلسات وسجل يوضح التعديل وسببه.
- مسار نسخ احتياطي يختاره المدير يدويًا، ونسخ SQL مع فحص واستعادة تجريبية مستقلة ونسخ دوري أثناء تشغيل الخدمة.
- كتالوج عرض وواجهة ويب للهاتف، ومعاينة مواد جديدة ومستلمين وروابط تجهيز الرسالة في واتساب دون إرسال آلي.
- إدخال مشتريات وتحديث متوسط التكلفة؛ حركة محاسبية مجمعة للموردين مع كشف تفصيلي لكل اسم مورد من حركاته.
- عملاء وحدود مديونية ومواعيد استحقاق وكشوف حساب.
- بيع نقدي أو آجل أو مدفوع جزئيًا، وحفظ سعر صرف الفاتورة والدفعة، وفحص المخزون والخصم وحد الدين.
- عرض آخر سعر بيع للمادة لنفس العميل مع العملة والوحدة والتاريخ والخصم.
- تحصيل للمدير فقط على صندوقه الخاص، وتوزيع التحصيل على أقدم فواتير العميل المفتوحة.
- إيصال قبض PDF عربي من ويندوز. الإيصال مصوّر عالي الدقة؛ النص غير قابل للبحث أو التحديد حاليًا.
- مرتجع مرتبط بفاتورة أصلية، يعيد المخزون وينشئ رصيدًا للعميل؛ صرف الرد النقدي غير منفذ بعد.
- إغلاق صندوق كل مستخدم بعد مطابقة الجرد بالدولار والليرة، ونقل الحصيلة إلى الصندوق الرئيسي دون إعادة إثبات الدين أو البيع.
- قيود مدينة ودائنة متوازنة، ومعاملات SQL ذرية، ومعرف طلب يمنع التكرار ويكشف تغيير محتواه عند الإعادة.
- سجل عمليات محفوظ بالمدخلات والمستخدم والتاريخ. تفاصيل كلمات المرور لا تدخل هذا السجل.
- موظفون مرتبطون بحسابات الدخول، دوام يدوي، راتب ثابت، هدف مبيعات ومكافأة مقترحة بعد تحقيق الهدف.

## حدود هذه النسخة

هذه **نسخة تطوير قابلة للتجربة وليست المنظومة النهائية المعتمدة للعمل الحقيقي**. الكتالوج وواجهة الهاتف يعملان محليًا. تطبيقات Android/iOS الأصلية والإرسال الآلي لواتساب والنشر الخارجي وHTTPS وإعدادات الجدار الناري غير منفذة، والربط الخارجي مؤجل بطلب المستخدم.

المتبقي يشمل: إلغاء وتعديل المستندات المعتمدة بضوابط كاملة، تغيير كلمات المرور من الواجهة، مصاريف وبنوك وسندات صرف عامة، إغلاق جماعي بتقرير دمج، طباعة فواتير البيع وكامل التقارير المالية وفروق الصرف، صرف مرتجع نقدي، الرواتب المعتمدة والصرف والسلف والإجازات والبصمة، وسياسة نسخ خارج السيرفر وحذف النسخ القديمة وترقيات إصدار عامة. التفاصيل في docs/RELEASE-0.2.ar.md.

العملة الأساسية لا تتغير من الواجهة بعد الإعداد. المدخلات المالية تدعم أربع منازل عشرية. لا توجد ضرائب مفعلة أو ادعاء امتثال ضريبي. المكافآت الحالية مقترحة على صافي فواتير الشهر بعد المرتجعات المسجلة عليها، ولا تنشئ صرفًا. قبل اعتماد سياسة المكافآت يجب تثبيت توقيت احتساب المرتجعات واعتماد الراتب.

## البناء والتحقق

```powershell
.\scripts\build.ps1
.\scripts\test-integration.ps1
```

اختبارات التكامل تنشئ قاعدة مستقلة باسم `MobiStore_Test_التاريخ_والوقت` وببيانات مصطنعة وكلمات مرور عشوائية غير مطبوعة. تُترك القاعدة للمراجعة ويُغلق خادم الاختبار في النهاية. لا تحذف أي قاعدة تلقائيًا.

نتائج آخر تشغيل في `artifacts/integration-results.txt`. المخطط الحالي في `docs/schema-v0.2.sql` لإنشاء قاعدة جديدة فقط. القواعد القديمة تتلقى إضافة AppRecords غير الهدامة بعد أخذ نسخة SQL للقواعد المهيأة. هذا ليس نظام ترقية عامًا لكل الإصدارات المستقبلية. آخر تحقق: 88 فحصًا ناجحًا، بما فيها ثلاث كاشيرات ونسخ واستعادة ومسار نسخ يحدده المستخدم.

## بنية المشروع

| المسار | المحتوى |
|---|---|
| src/MobiStore.Core | العقود وقواعد العملات والكميات وتوازن القيود |
| src/MobiStore.Server | ASP.NET Core، المصادقة، الصلاحيات، SQL Server وقواعد العمليات |
| src/MobiStore.Desktop | برنامج WPF عربي وتصدير إيصال PDF |
| tests | اختبارات القواعد والتكامل وتصدير الإيصال |
| docs | مخطط البيانات وخطة التنفيذ |

الخادم مقيّد افتراضيًا بالاتصال المحلي. لتشغيل أجهزة المحل الثلاثة والهاتف لاحقًا يجب إعداد عنوان الشبكة وشهادة TLS وحساب تشغيل محدود الصلاحيات وقواعد الجدار الناري. لا تفتح SQL Server مباشرة للإنترنت.

المراجع التقنية للإصدارات: [تنزيل .NET الرسمي](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)، [وثائق SQL Server Express](https://learn.microsoft.com/en-us/sql/sql-server/editions-and-components-of-sql-server-2025?view=fabric-sqldb).
